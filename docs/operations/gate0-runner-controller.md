# Installed finite collector controller

`InstalledCollectionController(InstalledRunnerCollection.from_installed()).run()`
composes the fixed A9 installation, actual job token owner, HTTPS projection
client, owned SSH sessions, lazy evidence core and actual collector root handoff.
The service wrapper owns its fixed secret-free exit code. There are no runtime
path, token, URL, process factory or completion callback arguments.

A uses eight token acquisitions: approval, two attesters and five issuer
submissions. Its issuer owns the only collector on its pipes. A's exact two
proofs feed issue/standing and consume/standing/replay. Actual issuer client3/EOF,
attester client0/EOF, root final/terminal joins and the concrete successful ACK
must complete before B approval, token, verification or SSH use. The original
independently anchored B not-before is awaited without changing either clock.
Each case activates separate public trust and verifiers capped at its original
expiry and monotonic deadline.

B uses seven non-withdrawal acquisitions and at most sixteen projection reads,
for a campaign maximum of31. Pending reads are distributed within the original
B interval, with each wait capped at5 seconds and at the remaining polling time
divided by the remaining intervals. Polling stops starting requests25 seconds before original expiry: two existing
request caps of5 seconds each plus15 seconds for final token/use, EOF and cleanup.
Pending waits target that same latest-start boundary. An applied response must
still leave strictly more than15 original seconds before later use; boundary
equality, exhausted time or sixteen pending reads refuses.
An applied response adds no wait. This pacing provides no network latency or
human response guarantee and never extends the original window. Those reads carry the installed human reference and
the authorization ID from the actual B issuer outcome. The controller never
withdraws approval or drains a relay. Only applied owner evidence permits the
existing later-use withdrawal refusal, issuer3/EOF and B root join/final EOF.
There are exactly four captured proofs; replay reuses the A consume proof.

The collector claims the exclusive private once marker before listener creation.
Failures cannot resume or rearm. All owned SSH/signing processes share one bounded
cleanup tail; the socket closes and the job credential is discarded on every
exit. Exact evidence is written only after both joins and receiver EOF, in a
new collector-owned0700 directory with exclusive0600 files. Existing output
cannot be overwritten. The private canonical `collection.json` retains full
collected evidence, exact root envelopes/joins, all raw projection responses and
public trust keys/records/floors/source qualification pins. JWTs, request
credentials, controller private keys and transport logs are excluded.

Installation construction is configuration validation, never proof of actual
root descriptor qualification or producer acceptance. The handoff independently
qualifies the actual peer and socket; see [collector root handoff](gate0-runner-collector-handoff.md).
`collection_complete` is separate from `readiness_accepted`, which remains false.
Producer, prerequisite, publication and recipient acceptance remain outstanding.
These focused tests cover controller sequencing and private output; they are not
a synthetic campaign gate or evidence that a protected installed run occurred.
