This source owns two fresh controller keys, installation of actual externally
issued public certificates, one local original-OIDC-credential courier, and
positive retirement of its own inodes. Its concrete JIT adapter observes one
literal systemd invocation and joins it to reader-owned protected job facts.

## Ordering and public source boundary

`InstalledA9Lifecycle.from_installed()` loads the fixed root installation and
external qualification. The initial loader does not read certificate inboxes,
frozen windows, final collection installation or bootstrap installation. Thus
`create_controller_keys()` runs before those descriptors exist.

1. Root claims the lifecycle once and creates A/B keys. Only public key bytes and
   controller fingerprints leave that phase through PublicKeySelection.
2. The authorized external CA custodian signs those actual public keys. The
   trusted installation owner delivers fixed public CA/certificate inbox files,
   freezes the original windows/packets using their real certificate digests, and
   writes the existing immutable collection installation and qualification.
3. `install_controller_certificates()` checks those actual bytes against the
   actual generated key pair, approved CA, exact original windows and fixed
   private/certificate installation pins, then creates final certificate files.
4. The trusted root delivery integration calls the private
   `_install_original_jit_config(encoded_bytes)` seam with actual encoded_jit_config
   from its existing authenticated off-host provisioning channel. This owner
   creates the fixed root0600 source itself and records actual ownership. It
   never pathname-adopts a credential or accepts JSON inode ownership. Bytes
   alone are not proof of a protected job or native qualification.
5. `receive_original_job_credential()` publishes its fixed private public-selection
   file and binds/chowns/journals/listens on the one-shot socket **before** starting
   the JIT unit once. It accepts one connection, internally obtains actual
   protected-job facts, measures the peer, receives one secret packet plus EOF,
   creates and reads back the original OIDC source, and sends a fixed acknowledgement.
6. Root runs the existing bootstrap. After actual collector retirement and before
   closing that same manager, it calls
   `retire_owned_files(manager, retirement_fact)`. Manager identity ownership and
   its live retirement fact are required. Successful collection is not required
   for safe file retirement after actual failed-but-empty collector retirement.
7. The job may then encrypt/upload E. Root's later fixed finalization path calls
   `_retire_owned_jit_invocation()` to stop and observe the same owned JIT
   invocation. Off-host registration and disposable allocation/volume destruction
   remain their actual provisioner's responsibility after export/job exit.

Each phase has a root-private create-only claim. Prior failure never rearms it.
A root-only journal can reopen its own committed identities for cleanup; it does
not retry generation, certificate installation, delivery or job launch. The fixed
root JIT source may retire after the admitted courier/collector chain has proved
credential delivery completed; systemd credential copies, runner decoded files
and ancestor memory remain separate retirement obligations.

If setup fails before an actual collector invocation exists, this module cannot
invent the same-manager collector retirement fact. Local cleanup is reported
unobserved; the exact off-host disposable-allocation owner must destroy its owned
instance at the existing bound. Native supervision must cover main-process crash,
normal exit and failure. Source files do not guarantee kernel progress or secure
erasure, and the current bootstrap is not assumed to already have ExecStopPost.

## Corrected recovery candidate (2026-10-16)

Collection references use the established closed `{path,digest}` schema only;
`digest` is `sha256:` followed by 64 lower-case hexadecimal digits. This applies
to shared packet, frozen window, certificate and private-key references. No
second installation shape or bare-hash compatibility path is accepted. Courier
measurement distinguishes the helper's parent PID from the socket peer PID and
repeats the same parent/UID/start measurement before admitting the peer.

The owner persists a create-only root-private `failed` marker when an operation
fails. Recovery restores it and every false historical retirement predicate as
sticky failure. It validates the journal chain before recovering individual
slots; a missing/replaced/anomalous slot cannot prevent recovery and attempted
cleanup of another independently owned slot. Stage recovery is isolated per
stage and cannot block unrelated final keys or credentials. Unknown ownership
and journal/write/fsync uncertainty prohibit success. If storage itself cannot
persist failure, no local successful cleanup claim is justified; the independent
allocation retirement remains required.

Only retirement can resume an existing, validated `phase-retire` claim. This
cleanup continuation retains the original deadline and existing identities; it
cannot repeat generation, certificate installation, credential delivery or JIT
startup. Before unlink the journal records the original slot/inode and actual
read predicate in a deletion intent. After unlink, parent fsync, absence and link
checks it records the terminal result. A crash between these records cannot
convert missing bytes into confirmed retirement: the unresolved intent is a
sticky failure while other safe targets are still attempted. No later handoff
or second retirement call clears earlier false observations.

Keygen requires Linux `waitid(WEXITED|WNOHANG|WNOWAIT)`, a retained pidfd, the
original child start/parent/UID identity and the default SIGCHLD disposition.
It observes an exited leader without reaping it. That unreaped child keeps its
PID/PGID allocated until the original group has been signalled, including when a
descendant holds an output pipe after leader exit. The original group is never
signalled after reaping its anchor. Group signal failure permits only a signal
to the retained child pidfd; it does not authorize UID-wide or guessed-PID
cleanup. Child wait, stream closure and UID emptiness checks remain within the
original reserved tail. An escaped session is a sticky failure; stage sealing
and promotion require actual empty observation. The fixed outer service
control-group/timer and independently owned allocation are its fallback.

JIT startup journals a one-start intent before requesting the literal start.
The first actual nonempty native InvocationID is held and journaled immediately,
including the activating/Python-wrapper interval, before readiness, cgroup
handle, pidfd or protected-job qualification. Failure cleanup with that captured
identity performs a fresh exact InvocationID read before requesting the literal
stop and refuses a replacement. Final retirement repeats the native final
snapshot after retained-event emptiness/process-exit observations. External
exclusive authority over the fixed unit is required: systemctl supplies no
atomic compare-and-stop operation.

A crash leaving only start intent and no captured InvocationID remains an
explicit lost-start failure. Recovery may perform bounded native reconciliation
but cannot adopt an invocation from timestamps, matching unit names or an
unsigned expectation. It does not stop an ambiguous/replacement invocation and
never rearms the job. The already selected outer BindsTo relationship, absolute
timer and actual allocation destruction are the independent fallback. Closing
this last capture gap requires a separately reviewed durable pre-exec identity
mechanism; this source does not claim it exists.

The focused source tests cover authoritative installation reuse, peer PID/PPID
