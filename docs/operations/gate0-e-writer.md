historical reader, producer reader and encryption owner. Its preparation result

refusal occur during the original A/B sequence and are verified from its retained

The binding pins the complete installed document, runtime UID, qualification,

official-verifier/handoff/framing source bytes. The root/native installation owner
must authenticate actual runtime measurements and retained decision provenance;
matching JSON hashes cannot recreate that history.

The qualification pins the document excluding its qualification pin, avoiding a
digest cycle. Its native receipt uses the existing `Gate0ENativeReviewReceipt.v1`
schema. Other selected evidence is under `/etc/dotmac-gate0-e/writer/`, each with
an exact `path`/`digest` pin. The selected source bundle is a distinct explicit
pin, never an alias for the module bundle. The two original retained cases are

## Exact producer and publication selection joins

Producer joins compare the observed workflow bytes and revision to the independent
`ESourcePins` and require the packet's job ID to equal the live reader's internally
selected workflow job. Another successful job in the same run does not substitute.

Publication installation additionally selects `reader_selection_digest` and a
closed `run` record: `repository_id`, `owner_id`, `workflow_id`, `run_id`,
`attempt`, `job_id`, `source_revision`, and `workflow_digest`. The first six are
positive integers with attempt exactly one; the revision is a full lowercase
commit SHA and the two digests are `sha256:` values. The selected publication
reader's root-authenticated installation and live selected job must match these
independent coordinates. Publication and completion readback use separately
qualified phase selections for the same actual run and workflow; no caller's
live-but-unselected run may supply the receipt's coordinates.

Historical comparisons omit only per-host retained-file locations for decisions
and packet sources. Repository paths, source revisions, blob IDs, retained-byte
hashes and historical tested-run coordinates remain significant. This permits
independently qualified hosts to retain identical evidence at different local
filenames without weakening evidence identity.

## Private failure boundary

Pure private verification, A9 export verification, installed loading, preparation,
receipt construction and final published readback execute behind concrete checked
helpers. A helper catches failures, detaches nested exception causes/contexts and
clears their completed traceback frames, then returns only a bounded internal
failure outcome. The public method drops its own payload, reader/fact and owner
argument references before raising a fresh generic `EWriterRefused` outside that
private handler. Suppressed display chaining alone is not the boundary.

On any installed-operation failure the consumed writer detaches all installed
private state, including retained pin bytes, selections and producer coordinates,
and remains used. It cannot retry or reuse those pins. Already staged partial
attempts remain for explicit disposition. A failed official-verifier call also
becomes a clean writer refusal; no successful readiness result is produced.
Keyboard interruption, bounded integer system exit, cancellation and generator
exit are scrubbed and re-raised as fresh stop signals, rather than continuing
verification or returning a proof. Private strings are not retained as exit
payloads. Cancellation cleanup does not manufacture success.

This is exception-reference hygiene. It does not claim memory zeroization,
erasure of caller-owned inputs, removal of independently retained files or
snapshots, or control over an external caller's frames. Successful pure APIs and
the four-file archive, canonical receipt schemas and all R2 joins are unchanged.
A bounded helper outcome is private control flow, not acceptance evidence.

Hosted source tests plant a private payload marker and inspect emitted exception
`__context__`, `__cause__`, this module's traceback locals and failed owner state.
Late failures follow actual unpack/proof/receipt/manifest checks, reconstructed
receipt plaintext, encryption/private staging and final published readback.
Deliberately retained internal completed work frames must also have empty locals.
Stop-signal tests verify cleanup and proper interruption after materialization.
These tests remain authored source; this repair runs only AST and Ruff checks.
