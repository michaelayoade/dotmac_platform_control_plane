# Gate 0 E sole writer (source preparation)

`gate0_e_writer` composes the existing retained-byte verifier, A9 export,
historical reader, producer reader and encryption owner. Its preparation result
is encrypted evidence; it does not accept E. C2's genuine withdrawal and later-use
refusal occur during the original A/B sequence and are verified from its retained
bytes. Foundation candidate allocation, ExecutionGrant and Lane 3 admission are
later operations and are not preparation inputs. Existing B/C1 decisions remain
selected historical evidence.

The default installed entry is `run_installed_prepare_e()`. The CLI
adapter belongs to the coordinator. It loads `/run/dotmac-gate0-e/writer.json`
and the independent `/etc/dotmac-gate0-e/writer-binding.json`. Both are protected
root-owned, canonical, bounded JSON read through the existing no-follow owner.
The binding pins the complete installed document, runtime UID, qualification,
native receipt and the actual writer/proof/archive/preparation/historical/GitHub/
official-verifier/handoff/framing source bytes. The root/native installation owner
must authenticate actual runtime measurements and retained decision provenance;
matching JSON hashes cannot recreate that history.

The qualification pins the document excluding its qualification pin, avoiding a
digest cycle. Its native receipt uses the existing `Gate0ENativeReviewReceipt.v1`
schema. Other selected evidence is under `/etc/dotmac-gate0-e/writer/`, each with
an exact `path`/`digest` pin. The selected source bundle is a distinct explicit
pin, never an alias for the module bundle. The two original retained cases are
constructed through `RootHostBinding`, `EPublicTrust`, `ERetainedCase`,
`ESourcePins` and `ESelection`. No current credential or private role key is read
to recover original identities.

Preparation reads the exact existing A9 export names, verifies manifest lengths
and digests, process-retirement success, the original manager invocation,
owned-file unlink/absence observations and the separately qualified actual
manager completion. It does not retire anything again. These schemas describe
retained observations authenticated by installed qualification; byte verification
does not recover historical SO_PEERCRED, process waits or cgroup observations.

A fresh concrete historical reader must own its returned facts. Comparisons use
selected repository/source/decision/test coordinates and retained decision byte
digests, excluding host-specific qualification/credential wrappers. A separately
installed concrete producer reader must own `COLLECTION_SNAPSHOT` facts for the
exact original producer. Its source-qualified stage policy enforces completed
collection/cleanup predecessor steps; the still-running upload job is not asked
to demonstrate its own future completion.

The private prerequisite container retains the actual historical reference
bytes, selected D/installed-composition evidence and actual A9 records. The
source-owned A7.7/D7/D11 coverage keys map to exact evidence references; they are
not B/C1/C2/D state flags or a replacement acceptance lifecycle. Operational
qualification must select applicable actual A8/A9/reverse-CA/coupled witnesses,
while existing accepted source mechanism tests cover source-testable rows. The
source cannot promote a status roster into those observations.

`prepare_encrypted_e` is invoked once with those bytes. Only
`gate0-evidence.pgp` and `gate0-evidence-public.json` are written, create-only,
to the preinstalled empty root-owned mode0700 staging directory
`/run/dotmac-gate0-e/staging`. Their modes are0600. Failed or partial attempts
are retained for explicit disposition. The only success output is
`E_FINALIZATION_COMPLETE`; plaintext and dossiers are never workflow outputs.

## B verifier interface

`verify_private_e(archive, selection, selected_inputs)` is pure and reusable by
the separate concrete B holder. `EPrivateInputs` contains the independently
selected original `EProducerCoordinates`, explicit source-bundle digest, exact
qualified prerequisite bytes, and actual projection/plaintext/ciphertext bytes.
It confers no authenticity itself. The B installed loader must authenticate its
original selections independently; caller-created dataclasses cannot substitute
for installed qualification.

The function unpacks the actual supplied plaintext through the existing archive
owner, matches the passed archive, reruns `verify_retained_collection`, recomputes
the existing producer/inner receipt/manifest bytes and verifies the actual public
projection hashes and prerequisite joins. The unchanged archive still contains
manifest.json and exactly collection.json, producer.json, prerequisites.json and
receipt.json. `PrivateEVerification` carries collection/prerequisite/producer/
receipt/manifest/plaintext/ciphertext/projection SHA256 digests and the fixed
result `private_archive_and_proofs_verified`; it carries no readiness flag.

## Receipt and future publication integration

`InstalledEWriter.construct_receipt(draft_reads, draft, publication_reads,
publication)` requires actual concrete readers with live-owned facts. It returns
only the canonical final receipt bytes for the separate mutation owner. It does
not create a draft, upload, publish or return acceptance. The closed B summary
schema is specified in `_receipt_document`; hashes are `sha256:` prefixed and
producer uses the existing `EProducerCoordinates.document()` shape.

Publication/readback use the distinct closed
`Gate0EPublicWriterInstallation.v1` selection and
`Gate0EPublicWriterBinding.v1`, at the existing fixed writer paths.
`Gate0EWriterInstallation.v1` accepts preparation only; there is no private-loader
fallback for publication. Public mode constructs `EPublicSelection`, containing
only policy/campaign, public source pins and Environment. It contains no
`ESelection`, root bindings, collection, prerequisites, operational payloads,
GPG/custody keys or private proof pins.

The independently qualified public selection pins the exact summary/projection,
closed public historical coordinates, holder source/profile expectations, source bundle,
producer coordinates, publication attempt and reader selection digests. Each
public retained purpose has one fixed slot under
`/etc/dotmac-gate0-e/writer/public/`: `qualification.json`, `native.json`,
`historical.json`, `summary.json`, `contract.json`, `decision.json`,
`provenance.json` and `projection.json`. Caller-selected paths are refused.
The source/native owner hashes and runtime UID remain authenticated by the fixed
protected binding. `Gate0EPublicWriterQualification.v1` and
`Gate0EPublicWriterNativeReview.v1` both require method scope
`public-evidence-publication-readback.v1`, matching source owners and exact reader
slots. Generated metadata cannot supply native qualification.

Only the exact closed `Gate0EBArchiveVerification.v2` summary is accepted. B owns
full decryption/private proof verification and derives its additional
`private_prerequisite_digest`, `source_reference_digest` and
`operational_evidence_digest` inside that successful verification. Publication
compares the genuinely selected holder source/profile, summary asset IDs/digests,
producer and policy to the actual public draft and projection. It obtains actual
completed producer facts from the separate fixed producer-completion reader and

`from_installed_public()` / `verify_public()`. The exact coordinate bytes must
equal its fixed `historical.json` slot, validated as
`Gate0EHistoricalSourceCoordinates.v1`. Full private wrappers and retained pins
refuse without fallback. The archived source digest
comes from B; a fresh host-specific historical wrapper cannot replace it.
The unchanged closed receipt uses those three B-authenticated digests, the exact
public projection and public producer/review/release facts. Public execution does
not rerun private proof parsing. The receipt omits its own digest, future asset ID
and future attestation.

`Gate0EPublicationDecisionProvenance.v1` binds exact contract/decision/native
receipt digests and reviewer ID. The closed
`Gate0EPublicationReviewContract.v2` requires the exact adopted human-review

`sha256:7a70090ef3a174ec0983f3a5e0abd9d80145ad3978d9498d639225db30504ba1`

`sha256:58b02290fa3f1dc72811be314c99040d6f9187148103e6c4c08a03e97709bd9c`.
This meaning attests actual qualified B verification for the displayed summary,

It grants no plaintext/key transfer or extended A9 lifetime. The independent

No installed operation, custody access, secret retrieval, release mutation,

## Exact producer and publication selection joins

Producer joins compare the observed workflow bytes and revision to the independent
`ESourcePins` and require the packet's job ID to equal the live reader's internally
selected workflow job. Another successful job in the same run does not substitute.

Publication installation additionally selects `reader_selection_digest` and a
closed `run` record: `repository_id`, `owner_id`, `workflow_id`, `run_id`,
`attempt`, `job_id`, `source_revision`, and `workflow_digest`. The first six are
positive integers with attempt exactly one; the revision is a full lowercase
commit SHA and the two digests are `sha256:` values. The selected publication
reader's root-authenticated installation and live selected job must match these
independent coordinates. Publication and completion readback use separately
qualified phase selections for the same actual run and workflow; no caller's
live-but-unselected run may supply the receipt's coordinates.

Historical comparisons omit only per-host retained-file locations for decisions
and packet sources. Repository paths, source revisions, blob IDs, retained-byte
hashes and historical tested-run coordinates remain significant. This permits
independently qualified hosts to retain identical evidence at different local
filenames without weakening evidence identity.

## Private failure boundary

Pure private verification, A9 export verification, installed loading, preparation,
receipt construction and final published readback execute behind concrete checked
helpers. A helper catches failures, detaches nested exception causes/contexts and
clears their completed traceback frames, then returns only a bounded internal
failure outcome. The public method drops its own payload, reader/fact and owner
argument references before raising a fresh generic `EWriterRefused` outside that
private handler. Suppressed display chaining alone is not the boundary.

On any installed-operation failure the consumed writer detaches all installed
private state, including retained pin bytes, selections and producer coordinates,
and remains used. It cannot retry or reuse those pins. Already staged partial
attempts remain for explicit disposition. A failed official-verifier call also
becomes a clean writer refusal; no successful readiness result is produced.
Keyboard interruption, bounded integer system exit, cancellation and generator
exit are scrubbed and re-raised as fresh stop signals, rather than continuing
verification or returning a proof. Private strings are not retained as exit
payloads. Cancellation cleanup does not manufacture success.

This is exception-reference hygiene. It does not claim memory zeroization,
erasure of caller-owned inputs, removal of independently retained files or
snapshots, or control over an external caller's frames. Successful pure APIs and
the four-file archive, canonical receipt schemas and all R2 joins are unchanged.
A bounded helper outcome is private control flow, not acceptance evidence.

Hosted source tests plant a private payload marker and inspect emitted exception
`__context__`, `__cause__`, this module's traceback locals and failed owner state.
Late failures follow actual unpack/proof/receipt/manifest checks in private
verification/preparation, public projection/receipt checks during publication,
encryption/private staging and final published readback.
Deliberately retained internal completed work frames must also have empty locals.
Stop-signal tests verify cleanup and proper interruption after materialization.
These tests remain authored source; this repair runs only AST and Ruff checks.

Successful `construct_receipt` releases the consumed writer's public
selection/retained-input references before returning the same canonical public
receipt bytes. The owner retains only `_used=True`; it cannot construct another
receipt or supply a later verification phase. Later independent verification
already requires a fresh separately installed writer. Publication captures the
public selected workflow digest before construction and preserves its exact
comparison afterwards. This change does not alter receipt/provenance/adoption,
source or policy checks, erase external retained evidence, access custody, or
claim memory zeroization. An authored hosted regression checks canonical output,
consumed state and clean one-shot refusal; local validation remains AST/Ruff only.
