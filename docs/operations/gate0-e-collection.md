# Private Gate0 E collection

`dotmac-platform gate0 collect-e` is installed but returns unavailable. The
protected two-case launcher, authenticated SSH-client terminal observation,
root cleanup export and protected input binding must be integrated before it
can execute. Source qualification does not close E.

`Gate0CollectedEvidence.v1` is private prepublication evidence. Its fixed fields
always report `readiness_accepted=false`, with producer, prerequisites, root
cleanup and publication acceptance pending. It must not be logged, emitted in
Actions outputs or uploaded as plaintext. Publication and archive policy remain
owner decisions outside this collector; there is no accepted-policy flag.

The fixed mechanism uses two predeclared finite channels. A issues, reads usable
standing, consumes once, reads consumed standing and reuses the exact envelope
and captured consume bundle for its terminal replay refusal. The pinned Control
a17 mapping is issuance `ENVELOPE_MISMATCH`; it counts only with the prior
matching committed spend, consumed standing and identical signed proof. B uses
a separate plan, request, window, lease, controller certificate and command. It
captures its consume proof before a real operator withdrawal, resolves the exact
human `external_ref` through Approvals' public immutable withdrawal read, and
reads the existing relay's exact durable APPLIED outcome by that withdrawal UUID.
The owner trigger uses this UUID as its event ID; the human reference is a
separate private provenance field and never substitutes for the event ID. The
collector checks the exact request, event, subject, plan and authorization,
then attempts use through current workload authentication and approval admission. The collector neither decides
approval nor withdraws it, directly revokes Control, drains production relay,
retries a mutation, renews a window or continues after terminal refusal.

`Gate0IssuerOutcome.v1` binds monotonic ordinal, credential-free request digest,
original window and registered proof/bundle digests to the actual owner result.
Confirmed issuance carries a committed issuer-command receipt readback;
consumption carries the owner's single-use reference. Expected withdrawal is
classified only after JWT signature/fixed claims/exact run/window/deadline
checks and confirmed owner-read rollback/close. Commit or cleanup uncertainty,
response loss, cancellation and generic refusals cannot satisfy either case.

Raw signed bundles remain byte-for-byte private. `export_registered` detaches
registered owner/companion/transcript bytes without exposing a verifier leaf or
registration hook, extending freshness or granting authorization. The service
sends digest references rather than oversized aggregate proof frames. It keeps
four-proof/512-KiB retention and existing 16-frame/2-MiB and eight-command bounds.

The hosted PostgreSQL fixture characterizes A through actual service framing,
owner transactions, synthetic signed SSH/custody material and actual pinned
refusal enums. It also exercises real Approvals withdrawal and relay revocation
for B. Component tests cover these owner seams; final qualification still needs
the actual protected two-start A/B campaign and native installed Linux
SSH/root-cleanup evidence. A full synthetic campaign is not an acceptance gate.
Fixtures do not establish
genuine human decisions, protected producer identity, host custody or archive
acceptance. Both terminal cases need separately authenticated actual root
cleanup; a worker's declared exit and sshd parent exit are distinct from the
SSH client's authenticated exit observation.
