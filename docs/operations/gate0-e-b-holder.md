# Gate 0 E B archive holder (source candidate)

The concrete B owner verifies the selected two-asset draft on the existing Mac
custody boundary. It does not accept E or publish a release. Its private record
stays at that boundary and its public result is the closed hash-only
`Gate0EBArchiveVerification.v1` summary expected by the sole writer.

These installation paths are **source conventions**, not measured or created
host configuration:

- `/Library/Application Support/Dotmac/Gate0E/B/installation.json`
- `/Library/Preferences/io.dotmac.gate0-e-b-binding.json`
- Root-qualified dossiers below `/Library/Application Support/Dotmac/Gate0E/B/`
- The selected runtime user's private
  `~/.config/dotmac-gate0-e-b/records` and `verified` directories

No installation, keyring or agent was created or inspected by this source work.
The actual existing holder runtime UID/home, GPG/gpgconf executable paths,
custody home, keyring, private-key directory and agent socket remain concrete
operational packet values. There is no new custody authority or approval state.

## Native Mac installation boundary

`InstalledBArchiveVerifier.from_installed()` requires Darwin, the actual runtime
UID matching the independent root binding and passwd home, and a real
`Gate0EBHolderNativeQualification.v1` dossier with `platform=darwin`. The root
binding pins the complete installation bytes, qualification, source-owner bytes
and the existing `Gate0ENativeReviewReceipt.v1`. Qualification pins the selection
excluding its qualification pin, avoiding a document digest cycle. It binds the
same native receipt, source-owner set, custody profile and exact GitHub/historical
reader installations. These selected records must originate from the actual
existing independent installation/native-review owner; matching JSON does not
authenticate its own measurements.

The custody profile is `Gate0EBExistingCustodyProfile.v1`. It binds the existing
runtime home, exact custody home, agent ownership boundary/root/socket, exact
keyring, the GPG default `private-keys-v1.d` directory, qualified public-recipient
profile, GPG/gpgconf tool pins, native receipt digest and actual current
qualification interval. It contains no private key or passphrase. Keyring and
private-key directory inspection here is metadata only; no secret-key file is
opened to recover identity.

The Mac-compatible reader walks every component with no-follow operations.
Root-owned prefixes must be protected from group/world writes; at the exact
selected private-user boundary, ownership must change to that runtime UID and
remain protected. Private records are0600, private directories/socket are0700.
Actual dev/inode/UID/mode observations of custody directories, keyring and agent
socket must equal the independently qualified native records before and after
GPG use and again before retaining the result. This uses native filesystem
metadata, not Linux `/proc`, a presumed mount, or a transferred Linux receipt.

The existing GitHub and historical owners currently retain their fixed `/run`
and `/etc` installed paths. This module does not mutate those constants, use
their private seals, or invent a Mac loader for them. Their exact installations
are selected by the Mac native qualification and must actually exist and be
qualified on that boundary. Without that genuine installation the operation
refuses. The source does not claim that Linux qualification transfers to Mac;
coordinator integration and concrete Mac packet review remain necessary.

## Decryption and actual process evidence

The archive owner's original `_run` signature and stdout-only encryption
semantics remain intact. Its private bounded process core now optionally owns a
separate status pipe. Only the internally generated decryption command enables
that pipe. The child inherits only its status write descriptor; plaintext stdout
and status are drained independently with finite bounds. Both must reach EOF,
all input must be written, the child must exit zero and be waited under the
original absolute deadline. Failures clear retained output, cancel the owned
process group and attempt bounded reaping inside that same deadline. Diagnostics
are fixed categories; stderr is discarded.

`decrypt_private_collection` uses the qualified root-protected executable,
existing homedir and exact existing keyring. It supplies no options file,
additional/default keyring, automatic key lookup/retrieval/import, passphrase,
agent-start authority or arbitrary command. Its explicit environment contains
only the selected existing HOME/GNUPGHOME and fixed locale/PATH. Gpgconf's actual
`--list-dirs agent-socket` result must equal the qualified socket before decrypt.
Both tool versions/hashes are checked. GPG's public listing checks the selected
primary/encryption fingerprint and current key validity/revocation.

Human unlocking stays on the existing B boundary before the operation. The
command uses `--no-autostart --pinentry-mode error`; unavailable locked custody
refuses rather than moving a passphrase through argv/environment/logs or
starting/importing another private context.

The already-produced format is one selected v3 PKESK plus AES256 integrity-
protected MDC data. The status parser requires exact `DECRYPTION_KEY` primary
and encryption fingerprints, selected `ENC_TO`, compatible
`DECRYPTION_INFO 2 9 [0]`, empty embedded filename, optional exact plaintext
length, and ordered `BEGIN_DECRYPTION`, `DECRYPTION_OKAY`, `GOODMDC`,
`END_DECRYPTION`. Unknown/error/duplicate/malformed/wrong-recipient/missing-
integrity status refuses. Exit-zero stdout alone is never decryption evidence.
Actual native GPG compatibility with this grammar remains a qualification
obligation; source fixtures do not establish it.

## Exact private and producer/source joins

`verify_draft(reads, draft_facts, *, deadline)` requires the exact concrete
`InstalledGate0GitHubReads` and its live-owned `DraftReleaseFacts`. It requires
exactly the original ciphertext/projection names, distinct selected asset IDs,
uploaded states, byte lengths and hashes, exact repository/owner/producer source
commit, and the independently selected installed reader policy bytes. It checks
that reader's original selected run/attempt/workflow and actual completed job
observations against the B installation's independent producer coordinates.
The existing draft reader already requires a completed original producer run;
the B verifier does not create a producer-completion DTO.

After actual decrypt, it calls existing `unpack_private_archive` and the frozen
sole writer's `verify_private_e` with independently reconstructed original
`ESelection`, `EProducerCoordinates`, source-bundle pin and exact selected private
prerequisite bytes plus the actual downloaded projection/ciphertext and actual
plaintext. The unchanged five-member archive and its inner receipt/manifest are
rechecked by their existing owners. Public original trust/floor/qualification
pins are loaded independently; no current key path is read to infer historical
issuer or attester identity.

A fresh actual installed historical reader must own its returned facts and match
the policy. Selected accepted source/decision/test coordinates and retained byte
digests must match both B's selected source dossier and the archived prerequisite
reference. Per-host qualification/credential wrappers are excluded from that
coordinate comparison. Actual reader installation bytes are checked again;
caller-created success flags or summary DTOs cannot substitute for live facts.

The private `Gate0EBPrivateArchiveVerification.v1` record binds actual draft
asset IDs/hashes, producer/source, ciphertext/plaintext/manifest/inner-receipt/
prerequisite/collection/projection hashes, selected recipient fingerprints,
actual validated status digest, native qualification/source/profile digests,
source-reference digest and verification time. It is retained create-only as a
mode0600 digest-named file in the preinstalled mode0700 `verified` directory.
The directory is held through a full no-follow traversal. No plaintext archive
or private key is written to a temporary file.

The public summary contains only the sole writer's closed schema:
repository/release/two asset IDs, original producer coordinates,
ciphertext/plaintext/manifest/private-receipt/projection/policy hashes,
private-verification-record hash, holder-source/profile hashes and the fixed
result `private_archive_and_proofs_verified`. All digests use `sha256:` prefixes.
The installed entry writes the exact canonical summary bytes to stdout without
adding bytes that would change its selected digest.

The summary is unsigned and cannot authenticate itself. Michael's proposed
digest-bound publication-review meaning remains UNADOPTED. Actual adoption and
the exact publication run's genuine human review are separate required evidence
for the sole writer; this B result supplies no readiness/publication authority.

actual child plaintext/status separation, bounds, EOF/deadline/nonzero cleanup,
fixed native installation refusal, spoofed reader facts, custody inode change
and seal refusal. Real subprocess fixtures claim only mechanism behavior;
no test creates/imports a private key or asserts native custody qualification.

project imports/tests/mypy/build/dependency installation, Docker, Git, host or
credential action occurred. Hosted tests/types and independent review remain
required before installing this source.

verification evidence, original custody and any partial release remain intact;
no automatic deletion/rotation/retry or risk acceptance is introduced.

## Independent review repair r2

The original producer workflow's authenticated byte digest must now equal B's
independently selected `ESourcePins.workflow_digest`, in addition to the exact
run, attempt, workflow ID, head and selected completed job. Native qualification
also checks the actual installed proof-finalization, root-handoff and framing
owner files directly. These joins are executable byte checks, not unchecked
metadata assertions or inherited writer qualification.

Private parsing/decryption/verification now ends in bounded checked helpers.
On failure they clear completed nested traceback frames, detach exception chains,
drop private plaintext/status/archive/record references and return only a closed
failure category. Public wrappers drop private arguments before emitting a fresh
generic refusal outside the private handler. Consumed B state discards retained
private bytes and detaches its selection/profile on both success and failure.
Interrupt and exit categories are re-raised cleanly; a cancellation cannot become
a verification success. These are reference/traceback protections, **not proof of
memory zeroization** or control over the existing GPG agent's memory.

The directory walk transfers ownership of each newly opened directory descriptor
before checking the stat/open identity, so both parent and child are closed when
a replacement race refuses.

The r2 hosted fixtures begin with a complete valid signed archive and public
projection, real fixed B/GitHub/historical loaders, actual concrete reader fact
issuance through the HTTP seam and the private record writer. Only native
protected-file/metadata and typed GPG/decrypt boundaries are simulated. They do
not replace `owns_facts`, use reader seals or establish real custody. Positive
composition, independent workflow and owner-byte changes, copied/foreign facts,
wrong original job, custody drift, single HTTP asset changes, descriptor races,
and failures after decrypt/unpack/proof/private write inspect clean exception
contexts and retained source-frame locals. Those tests remain authored for
hosted execution; AST/Ruff checks alone do not establish their runtime outcome.
